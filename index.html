1. JavaScript Fundamentals

Answer

JavaScript is a high-level, dynamically typed programming language used extensively in browsers and also on servers through runtimes such as Node.js. It supports object-oriented, functional and asynchronous programming. In frontend development, JavaScript controls application behavior, UI state, API communication and browser interaction. Example: React itself is JavaScript-based; React components, hooks and state logic ultimately execute as JavaScript.

Answer

var is function-scoped and can be redeclared. let and const are block-scoped. let can be reassigned, while const cannot be reassigned after initialization. let and const are hoisted but remain inaccessible in the temporal dead zone until initialization. In modern code I prefer const by default and let when reassignment is necessary.
var a = 10;
let count = 1;
const name = "Abhijit";
count = 2; // valid
// name = "X"; // TypeError

Answer

Scope determines where a variable can be accessed. JavaScript has global scope, function scope and block scope. let and const respect block scope, while var is function-scoped.

if (true) {
  let x = 10;
  var y = 20;
}
// console.log(x); // ReferenceError
console.log(y); // 20

Answer

Lexical scope means a function's access to variables is determined by where the function is written in the source code. A nested function can access variables from its outer lexical scopes.

Answer

Hoisting describes how JavaScript processes declarations before executing code. Function declarations can be called before their declaration. var is initialized to undefined, while let and const are hoisted but inaccessible before initialization because of the temporal dead zone.

sayHi();
function sayHi() { console.log("Hi"); }

Answer

The temporal dead zone is the period between entering a scope and the point where a let or const declaration is initialized. Accessing the variable during that period throws a ReferenceError.

console.log(x); // ReferenceError
let x = 10;

Answer

A closure is created when a function retains access to variables from its lexical scope even after the outer function has finished executing. Closures are useful for private state, factories, callbacks and function-based encapsulation.

function counter() {
  let count = 0;
  return () => ++count;
}
const next = counter();
console.log(next()); // 1
console.log(next()); // 2

Answer

An execution context is the environment in which JavaScript code executes. It contains information such as variable bindings, scope information and the value of this. The global context is created first, and function contexts are created when functions execute.

Answer

The call stack tracks currently executing functions. When a function is called, a stack frame is added; when it returns, the frame is removed. Deep or infinite synchronous recursion can cause a stack overflow.

function one() { two(); }
function two() { console.log("running"); }
one();

Answer

Primitive values such as string, number, boolean, bigint, symbol, null and undefined are values themselves. Objects, arrays and functions are reference types in practical terms: variables hold references to objects. Assigning an object variable does not create a new object.

const a = { name: "A" };
const b = a;
b.name = "B";
console.log(a.name); // B

Answer

A shallow copy duplicates the top level but nested objects remain shared. A deep copy creates independent nested structures. Spread syntax and Object.assign are shallow. structuredClone is a modern option for supported data.

const a = { user: { name: "A" } };
const b = { ...a };
b.user.name = "B";
console.log(a.user.name); // B

Answer

Destructuring extracts values from arrays or properties from objects into variables.

const user = { name: "Abhijit", age: 37 };
const { name, age } = user;

Answer

The syntax is the same, but the meaning depends on context. Spread expands an iterable or object into individual elements/properties. Rest collects remaining values into an array or object.

const a = [1,2];
const b = [...a,3]; // spread
function sum(...nums) { return nums.reduce((a,b)=>a+b,0); } // rest

Answer

this is determined mainly by how a function is invoked. In a method call it normally refers to the object before the dot. call, apply and bind can explicitly control it. Constructors use it for the new instance. Arrow functions do not create their own this and capture it lexically.

const user = {
  name: "Abhijit",
  greet() { console.log(this.name); }
};
user.greet(); // Abhijit

Answer

All three can control this. call invokes immediately with arguments individually; apply invokes immediately with arguments as an array; bind returns a new function with this and optionally initial arguments fixed.

function greet(city) { console.log(this.name, city); }
const user = { name: "Abhijit" };
greet.call(user, "Pune");
greet.apply(user, ["Pune"]);
const fn = greet.bind(user, "Pune");
fn();

Answer

A prototype is an object from which another object can inherit properties and methods. JavaScript uses prototype-based inheritance. When a property is not found on the object, JavaScript searches its prototype chain.

Answer

The prototype chain is the sequence of objects JavaScript searches when resolving a property or method. It continues until the property is found or the chain reaches null.

Answer

JavaScript classes provide class syntax, but inheritance is still implemented through prototypes. Classes make object-oriented code easier to express while the underlying model remains prototype-based.

class User {
  greet() { return "Hello"; }
}
const u = new User();
console.log(u.greet());

Answer

map transforms every item and returns an array of the same length. filter returns items that satisfy a condition. reduce combines items into one accumulated result.

const nums = [1,2,3,4];
const doubled = nums.map(n => n * 2);
const even = nums.filter(n => n % 2 === 0);
const total = nums.reduce((sum,n) => sum + n, 0);

Answer

Immutability means creating a new value instead of directly changing the existing state object. React and Redux rely heavily on reference comparisons to detect changes efficiently. Immutable updates make state transitions predictable and easier to debug.

setUser(prev => ({ ...prev, name: "Abhijit" }));

Answer

Arrow functions don't have their own this, arguments, super, or new.target — they lexically inherit this from the enclosing scope, so they can't be used as constructors and are a poor fit for object methods that rely on this. Regular functions get their own this (determined by how they're called), receive an arguments object, and can be used with new. Arrow functions also can't be generators.

const obj = {
  name: "Abhijit",
  regular: function () { console.log(this.name); },
  arrow: () => console.log(this?.name),
};
obj.regular(); // "Abhijit" (this === obj)
obj.arrow();   // undefined (this is lexical, not obj)

Answer

A function that takes one or more functions as arguments, returns a function, or both. They enable composition and abstraction over behavior — map, filter, reduce, and event-handler factories are all higher-order functions.

function withLogging(fn) {
  return (...args) => {
    console.log("calling with", args);
    return fn(...args);
  };
}
const add = (a, b) => a + b;
const loggedAdd = withLogging(add);
loggedAdd(2, 3); // logs "calling with [2, 3]", returns 5

Answer

Currying transforms a function that takes multiple arguments into a sequence of functions that each take a single argument, returning a new function until all arguments are supplied. It enables partial application and reusable, specialized functions.

const curry = (fn) => (...args) =>
  args.length >= fn.length
    ? fn(...args)
    : (...more) => curry(fn)(...args, ...more);

const add3 = (a, b, c) => a + b + c;
const curriedAdd3 = curry(add3);
curriedAdd3(1)(2)(3); // 6
curriedAdd3(1, 2)(3); // 6

Answer

A function expression that runs as soon as it's defined, creating an isolated scope. Before ES modules and block-scoped let/const, IIFEs were the standard way to avoid polluting the global scope and to encapsulate private state (the module pattern).

const counter = (function () {
  let count = 0;
  return { increment: () => ++count };
})();
counter.increment(); // 1

Answer

Default parameters supply a fallback value when an argument is undefined. Rest parameters (...args) collect any remaining arguments into a real array. The legacy arguments object is an array-like (not a real array — no map/filter) available only in regular functions, not arrow functions, and reflects exactly what was passed in, not the defaults applied.

function greet(name = "Guest", ...rest) {
  console.log(name, rest);
}
greet("Abhijit", "Pune", "India"); // "Abhijit" ["Pune", "India"]
greet(); // "Guest" []

Answer

A pure function always returns the same output for the same input and produces no observable side effects — no mutating arguments, no I/O, no reliance on external mutable state. Pure functions are easier to test, memoize, and reason about, which is central to React's rendering model and Redux reducers.

// Pure
const addPure = (a, b) => a + b;

// Impure — mutates external state
let total = 0;
function addImpure(n) { total += n; return total; }

Answer

A generator function (function*) can pause and resume execution using yield, returning an iterator. Each call to .next() runs until the next yield, making generators useful for lazy sequences, custom iterables, and — historically — flow control before async/await.

function* idGenerator() {
  let id = 1;
  while (true) yield id++;
}
const gen = idGenerator();
gen.next().value; // 1
gen.next().value; // 2
